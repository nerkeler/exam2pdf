## PDF 导入的分发方式

旧方案依赖各架构的 Poppler 运行库，2026-10-25 的三次构建因缺少该运行库而在预检停止。当前改为随应用打包 `pdfjs-dist` 6.4.299，用 Electron 自带 Chromium canvas 在独立受限渲染页面中转换 PDF。转换在本机执行，不需要用户安装 Poppler，不会为转换上传文档。

打包必须保留 PDF.js 主模块、worker、CMaps、标准字体、色彩配置、WebAssembly 解码资源及各自许可证。依赖通过 `package-lock.json` 固定，不从在线 CDN 加载转换脚本。第三方声明见 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)。

## 构建命令

需要 Node.js 22.13.0 或更新的受支持版本。先执行 `npm ci`；项目 `postinstall` 会调用官方安装器下载并校验本机 Electron 运行时。若使用 `--ignore-scripts`，需随后运行 `npm run electron:install`。

```sh
npm ci
npm test
# 在图形会话中验证实际 PDF 转图
npm run test:pdf

# macOS Apple Silicon
EXAM2PDF_BUILD_ARCH=arm64 npm run dist:mac

# macOS Intel
EXAM2PDF_BUILD_ARCH=x64 npm run dist:mac

# Windows x64
npm run dist:win

# Linux
npm run dist:linux

# 只检查依赖和打包资源，不生成安装包
node scripts/package-app.cjs mac --check-only
node scripts/package-app.cjs win --check-only
node scripts/package-app.cjs linux --check-only
```

Windows PowerShell 的架构设置写法为 `$env:EXAM2PDF_BUILD_ARCH = 'x64'`。构建脚本固定使用 `--publish never`，本地输出到 `release/`，构建命令自身不会创建 GitHub Release。

需要代理时，macOS/Linux 可使用 `ELECTRON_GET_USE_PROXY=1 npm ci`；PowerShell 先设置 `$env:ELECTRON_GET_USE_PROXY = '1'`。Electron npm 包安装与运行时二进制下载是两个步骤；用 `npm start -- --check-only` 检查后者是否可用。

1. 安装、首次启动、退出、重启与卸载，核对应用身份、路径及用户数据位置。
2. 小红书扫码登录、重启后会话、搜索覆盖控件、详情采集和缺页重试。
3. 图片、文件夹和 PDF 作答导入，包含中文/空格路径、多页 PDF、24 页及 50 MB 限制提示；转换不得依赖开发机外部工具。

5. 批阅确认、错题归档、训练审核、备份导出/恢复与手机同网段上传。
6. AI 配置、密钥保存及重启、发送确认、网络失败和模型不支持图片的处理。
7. 核对最终产物中的第三方许可、签名、公证和升级数据兼容性。
