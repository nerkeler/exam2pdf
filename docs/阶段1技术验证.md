# 阶段 1：技术验证记录

日期：2026-10-19（持续更新）
状态：已补 Electron 原型入口，使用 `WebContentsView` 在应用窗口内作为顶层网页打开小红书，并配置 `persist:xhs` 会话。历史记录曾确认真实窗口扫码登录和退出重启后会话保留；本轮未复验。Electron 44.9.0 运行时的 Node 模式检查已通过。真实窗口冒烟曾在锁屏桌面触发 macOS `RegisterApplication` 的 `SIGABRT`，早于应用主进程代码；当前桌面仍锁定，因此工作台首帧、小红书二维码、登录会话、真实采集及打印仍未验收。主窗口加载失败、渲染进程崩溃和首帧超时现有可见诊断路径。

## 目标

确定核心流程的实现入口：用户在采集浏览页中直接打开小红书网页并登录，随后由运行在小红书页面上下文的脚本采集图片；同时验证图片导入、手机局域网上传、图片排序和 PDF 输出。验证原型位于 [`spikes/phase1/`](../spikes/phase1/)；网页登录不需要开放平台 ID，本地原型不接触账号凭据。

## 本地验证原型

- `spikes/phase1/server.py`：早期独立验证服务，绑定局域网网卡，使用临时令牌接收图片；仅供技术验证，不是 Electron 正式路径。
- `spikes/phase1/index.html`：早期验证页，包含图片选择、手机上传、排序和 A4 分页打印。
- `electron/mobile-upload-server.cjs`：Electron 内的临时手机上传服务；显式开启后绑定本机网络端口，上传图片写入应用本地作答记录。应用退出后地址令牌失效。
- `docs/原型图.html`：Electron 启动时加载工作台，小红书通过独立网页视图覆盖采集区域；普通浏览器只显示 Electron 提示。采集按钮由 `frontend/exam2pdf.user.js` 注入，采集后写入 Electron 本地帖子库。
- `electron/post-store.cjs`：按帖子分目录保存 JSON 元数据和图片，位于 Electron `userData/library/posts/`；采集图片不会写进项目仓库。
- `electron/print-document.cjs`：生成按图像方向分页的 A4 打印文档，供 Electron 打印或导出 PDF。
- 上传文件仅落在系统临时目录 `exam2pdf-phase1-uploads/`，服务退出后令牌失效；该验证服务不连接公网，也不用于正式部署。

5. 用真实手机完成同 Wi-Fi 上传验收；HEIC 导入仍未实现。

## 运行方式

在项目根目录运行：

```bash
python3 spikes/phase1/server.py
```

使用终端输出的本机链接在电脑打开页面；手机使用同一行输出的局域网链接。测试完成后在运行终端按 `Ctrl+C` 停止服务。
