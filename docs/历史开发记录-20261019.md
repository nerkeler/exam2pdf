# exam2pdf 开发计划

目标：把“小红书找试卷 → 采集整理 → 打印给学生 → 收回作答 → 批阅 → 错题与学情 → 针对性训练”连成一条桌面工作流。

## 产品边界

- 小红书在 Electron 窗口中作为真正的网页打开；用户在网页内登录、浏览并主动选择笔记采集。
- 空白试卷只进入整理和打印流程。批阅只接收学生完成后的作答页，不在空白试卷详情上放“加入批阅”。
- 首版优先保证单机、本地数据和单个学习者流程；手机上传与 AI 接口在需要时通过本机服务接入。
- 公开市场已有“卷卷侠”覆盖小红书试卷图采集、分类和打印。因此项目重点放在采集结果直接进入本地帖子池，以及后续批阅、错题和学情闭环；Electron 外壳本身不作为主要差异点。

## 阶段与验收

### 阶段 0：Electron 启动与登录验收

**现状：** Electron `BrowserWindow`、小红书 `WebContentsView`、`persist:xhs` 和采集脚本注入已经写入项目。历史开发记录曾记载真实窗口扫码登录与会话保留，但这轮未重新验收。启动脚本要求 Electron 主版本与项目依赖一致，并清楚报告缺失/不匹配运行时；主窗口加载失败、渲染进程崩溃或 15 秒内没有首帧时会显示错误页，而不再无限隐藏等待。帖子库、作答库或训练库在创建主窗口前初始化失败时，现在也会打开应用内诊断页，展示经过 HTML 转义的错误信息；只有诊断窗口自身无法创建时才退回系统错误对话框。另已将小红书网页视图和采集脚本设为可降级组件：初始化失败或脚本缺失会显示状态并保留工作台窗口，相关错误处理有自动化测试。工作台初始化阶段的同步脚本异常或未处理拒绝也会在页面中显示错误信息；首帧超时、加载拒绝、渲染崩溃、正常首帧和窗口销毁均有启动监控测试。项目依赖 Electron 44.9.0；本机已安装匹配运行时。`npm start -- --check-only` 会在不创建窗口的 Node 模式下实际启动 Electron 并核对版本，当前已通过。README 已说明从项目根目录运行 `npm start`；直接打开 Electron 运行时会显示 Electron 自带欢迎页。新增 `npm run smoke:startup`，在临时数据目录运行真实 Electron、跳过小红书网络视图，并检查工作台初始化标记和首帧事件；本次在锁屏桌面尝试时，Electron 在 macOS `RegisterApplication` 阶段收到 `SIGABRT`，早于应用主进程代码，因此该冒烟尚未通过，需解锁后重试。工作台 HTML 行内脚本语法及静态 DOM ID 唯一性也纳入回归测试。桌面当前仍锁定，因此实际冷启动、工作台首帧、小红书二维码和登录会话验收待解锁后进行。

**交付：** 从项目入口稳定打开 exam2pdf 工作台和小红书网页，而不是 Electron 默认欢迎页；登录、浏览器前进/后退/刷新正常。

**验收：** 登录二维码可见；扫码成功；关闭并重开应用后登录状态仍在；小红书网页不会覆盖工作台导航或底部操作区。

### 阶段 1：采集笔记并写入本地帖子池

**实现进展（2026-10-19）：** Electron 采集预加载桥、笔记详情页识别、图片读取、本地文件存储和帖子池联动已经实现。重复采集按笔记 ID 去重；部分图片失败会记录缺页数量，再次采集时补齐缺页。近期审查发现主进程曾漏转发预期图片数，已修复并增加覆盖“部分采集后重试补齐”的帖子池集成测试。帖子池已连接本地数据，可搜索、重命名、删除、预览，重启后从本地清单恢复。存储与重试逻辑已有自动化测试；小红书 HTTPS 主机、笔记路由、图片 CDN 校验已抽离并覆盖仿冒域名测试。采集注入脚本另有 VM 集成测试，模拟详情数据、图片桥和帖子池桥，验证采集元数据及图片宽高，并确认信息流页面不会写入帖子池。此次审查还修复了状态中空图片链接被过滤后导致后续页码前移的问题；现在空链接页会记为失败，成功图片仍保留原始索引，后续重试可补到正确页。新增端到端 VM→PostStore 测试：第一次跳过无链接页并保留缺页记录，补齐链接后重采，验证图片按原页序写入且缺页清零。真实小红书笔记采集仍待 Electron 窗口验收。

**交付：** 用户在小红书笔记详情页点击右下角“采集到 exam2pdf”；采集该笔记的图片、标题、作者、原帖链接和采集时间，保存为一条本地记录。采集状态和失败页数要明确显示。

**验收：** 单图、多图笔记均能采集；缺图或加载失败会提示并允许重试；重复采集有明确处理方式；应用重启后帖子和图片仍在；采集不会误把信息流卡片或无关图片当成试卷页。

### 阶段 2：帖子池、图片整理与打印

**实现进展（2026-10-19）：** 详情页显示真实图片缩略图和大图预览；桌面原生拖动、触屏拖动手柄、前后移动、移除图片及在详情追加本地图片都会写入本地清单。追加图片与小红书原帖页数分别计数，不会占用待补采图片页码；重复采集补齐缺页时也会把本地补充页保留在末尾。触摸排序逻辑有事件级自动化测试，补充图片有存储、页码冲突和缺页重试测试；页面测试检查详情入口、IPC 桥及持久化调用。帖子详情可生成 A4 PDF（按图片方向排版）或打开系统打印窗口，本地图片和文件夹可导入为帖子。打印布局已有自动化测试；打印成功、用户取消、打印调用同步异常或关闭窗口异常时，都会清理临时打印文件，相关清理路径有自动化测试。实际打印预览和横竖页纸张效果待 Electron 窗口验收。

**交付：** 帖子池支持预览、搜索、重命名和删除；详情页支持拖动排序、移除图片、补充本地图片；生成 PDF 或打开打印预览。导入的本地图片也能整理打印。

**验收：** 图片顺序在保存和重启后不变；竖图、横图、长图和较大图片均可预览；PDF 页序、方向、缩放和留白正确；打印失败时保留原图和整理状态。

### 阶段 3：学生作答收集与批阅

**实现进展（2026-10-19）：** 已完成电脑图片/摄像头/PDF 导入、独立本地作答记录、图片排序及人工逐题批阅。PDF 通过本机 Poppler `pdftoppm` 转成最多 24 张 JPEG；开发环境需要 Poppler 命令可用，分发包需要随应用提供相应平台的转换程序。手机上传已接入 Electron：用户手动开启后生成随机短期地址，手机网页提交的 JPG、PNG、WebP 照片直接保存到本地作答记录。新增本机 HTTP 回环集成测试，实际启动临时端口、提交图片并验证落库，关闭服务后确认地址失效；真实手机和同一 Wi-Fi 验收仍待用户稍后验收。AI 接口配置保存在本机，API Key 经 Electron 系统安全存储加密；文本连通性测试不发送学生图片；用户逐条确认后才会将作答图片发送到所配置的 HTTPS 视觉模型，返回逐题批阅草稿供家长编辑。草稿不会自动确认；确认结果才会进入错题和统计。请求构造、响应校验、连接测试和错误处理有模拟服务自动化测试；两页 PDF 样本已在本机 Poppler 运行时完成实际转换；真实服务商调用尚待配置和验收。

**交付：** 批阅页单独接收已完成的答题照片/PDF，支持电脑导入和手机局域网上传；AI 输出逐题结构化草稿，家长可以修正后确认。

**验收：** 已完成图片/PDF 作答页本地保存、页序调整、逐题判定、草稿/确认持久化，以及手机上传请求处理、真实本机 HTTP 回环和存储测试。PDF 转换模块覆盖页数上限、临时文件清理和错误处理；两页样本通过本地 Poppler 实际转换。AI 请求使用模拟服务验证图片数据格式、响应规范化和失败处理。实际 AI 服务、真实手机跨设备上传和 Electron 界面验收待用户稍后验收。

### 阶段 4：错题本与个人学情

**实现进展（2026-10-19）：** 错题只由已确认的批阅记录派生；状态变更写回批阅记录。支持状态、日期范围、知识点、错因筛选；学习页从本地记录计算近 30 天批阅数、题目正确率、错因及薄弱知识点，无记录时显示数据不足。核心统计逻辑有单元测试。

**交付：** 仅将确认后的错误、部分正确和未作答题归档；支持按日期、知识点、错因筛选，标记掌握状态；展示近期正确率、错因和薄弱知识点。

**验收：** 统计只使用已确认的批阅记录；修改掌握状态或删除作答时相关错题和指标会重新派生；没有题目记录时不展示正确率。

### 阶段 5：针对性训练与闭环验证

**实现进展（2026-10-19）：** 已加入本地题型模板，可按薄弱知识点生成方程、有理数、分数与几何练习；另可将选中的知识点发送到已配置的 HTTPS AI 服务生成练习草稿，不会发送学生作答图片。AI 响应限制大小、要求恰好五道完整且不重复的题目；结果仍为未审核草稿。练习题和家长审核状态保存在本机，并纳入数据备份。家长检查题目与答案后可确认并打印；批阅时可把作答关联到已审核练习。训练完成状态从关联作答中派生，只有批阅结果确认后才计为完成；删除作答后统计会自动回退。答案默认收起，打印时题目与答案分开分页。新增模拟 AI 接口测试；真实服务商与内容质量仍需配置后人工验收。

**交付：** 从薄弱知识点生成变式练习，题目与答案分开，家长审核后可打印；学生完成后再次批阅并更新掌握情况。

**验收：** 本地题型生成、AI 草稿解析与输入校验、训练历史持久化、家长审核状态、备份恢复、作答关联和打印分页已有自动化测试；完成状态只认关联的已确认批阅，并随作答删除或批阅修改重新计算。真实 AI 内容仍需家长检查，真实服务商调用待验收。

### 阶段 6：备份、恢复与桌面分发

**交付：** 本地数据备份/恢复、Mac 与 Windows 打包（包含 PDF 转换工具）、首次运行说明和升级检查。

## 验证方案

每阶段按实际风险选择验证，不把一种检查当成全部通过：

1. **静态检查：** JavaScript/主进程语法、格式和数据结构校验。
2. **单元测试：** 图片清单、排序、重复项处理、PDF 页面参数、批阅结果解析、学情统计等纯逻辑。
3. **集成测试：** Electron IPC 到本地存储、数据重启恢复、手机上传、本地 AI 请求及失败重试。
4. **界面验收：** 在桌面和窄屏视口检查导航、采集按钮位置、拖动排序、预览和打印对话框。
5. **真实外部验证：** 用真实小红书账号确认二维码、会话恢复、笔记图片采集；有配置时再验证真实 AI 提供商。外部服务不可用时保留模拟数据验证，不把模拟结果记为外部集成通过。
