# exam2pdf · AI 错题分析与训练 · 需求文档

> 版本 v1.4 · 2026-10-18（v1.3 Electron 壳 → v1.4 增加内嵌小红书采集浏览器，免除扩展安装）
> 交互形态：双击桌面图标 → 内嵌小红书浏览器采集 → 帖子池/批阅/错题本全在应用内；窗口与手机（局域网）同走一个内嵌 Hono 服务
> 定位：在现有工具之上增加「AI 接入」能力，把批阅结果沉淀为**错题本 → 薄弱点画像 → 针对性训练**的学习闭环。
> 原则：**双击可用、零原生依赖、数据本地自持、AI 是增强而不是依赖。**

---

## 1. 背景与目标

现状：工具已覆盖「小红书采集 → 打印 → 拍照合成 PDF → 手动触发 AI 批阅」。

问题：批阅结果是一次性 Markdown，看完即丢；照片必须先传到电脑；AI Key 存浏览器易丢。

目标：引入**本地轻后端**，把批阅结果沉淀为错题本，积累**薄弱点画像**，生成**针对性训练**，并支持**手机直接拍照上传**——形成闭环：

```
批阅 → 错题归档 → 薄弱点分析 → 变式训练 → 再批阅（验证是否掌握）
```

用户角色：
- **家长**：操作者（上传、确认、查看报告）
- **学生**：作答者、训练执行者

## 2. 底层选型评估（v1.2 修订记录）

### 评估维度（按本项目实际权重）

| 维度 | 权重 | 说明 |
|---|---|---|
| 分发成本（给非技术家长） | ★★★★★ | 对方是「双击都不会排查问题」的用户，杀毒软件误报/安全弹窗=流失 |
| 原生依赖 | ★★★★★ | 每多一个 native 模块（node-gyp/prebuild），跨平台分发多一类故障 |
| 维护者熟悉度 | ★★★★ | 你是唯一维护者，JS 生态内解决 |
| 能力覆盖 | ★★★ | AI 代理（SSE）、静态托管、文件上传、局域网——都是基础能力 |
| 性能/体积 | ★ | 家庭规模（个位数用户、千条级数据），任何方案都够 |

### 候选方案对比

| 方案 | 分发 | 原生依赖 | 维护 | 能力 | 结论 |
|---|---|---|---|---|---|
| **A. Node 22 LTS + Hono + JSON 文件存储，便携 zip 发行** | 解压即用（内置 node.exe，无安装无编译） | **零原生依赖** | Node 生态最稳、资料最多 | 覆盖全部需求 | ✅ **采用** |
| B. Bun + Hono + bun:sqlite，`build --compile` 单文件 | 单文件 90MB，但**未签名 exe 被 Windows Defender/SmartScreen 高概率误报拦截**，家长无法自行处理 | 零 | Bun on Windows 成熟度一般、版本迭代快 | 覆盖 | 缓议：单文件体验好，但误报是分发硬伤 |
| C. Electron / Tauri 桌面应用 | 安装包体验最完整、可自动更新 | Electron 零原生；Tauri 需 Rust | Electron 加重但 JS 友好；Tauri 需 Rust 学习成本 | 覆盖 | 暂缓：当前无桌面级 UI 需求，体积/构建复杂度不值 |
| D. Go（net/http + embed + 纯 Go sqlite） | 单文件 ~15MB，交叉编译一条命令，误报最少 | 零 | **需要你写 Go**，长期维护语言切换成本最高 | 覆盖 | 暂缓：选型正确但与维护者技能不匹配 |
| E. 纯前端 BYO Key（v1.0） | 双击 HTML | 零 | 最低 | **受 CORS 限制、Key 随浏览器丢、无手机上传** | 已排除 |

### v1.2 → v1.3 补充：Electron 壳

在 v1.2（Node 便携发行）基础上加 Electron 外壳：**后端代码零重写**（Hono 进主进程），获得桌面应用形态、内置 Chromium（环境版本可控）、electron-updater 自动更新。代价：安装包 60-90MB、IPC/构建工具链学习。

### v1.1 → v1.2 的两处修正

1. **Bun compile → 便携 Node zip 发行**：未签名编译 exe 在 Windows 上被杀毒拦截的客服成本，高于多带一个 node.exe（70MB）的体积成本。解压双击的体验等价，可靠性更高。
2. **bun:sqlite → JSON 文件存储**：better-sqlite3 需原生模块（跨平台分发故障源），bun:sqlite 绑定 Bun。家庭规模（千条级记录）JSON 文件完全够用——用纯 JS 读写 `data/db.json`，把原生依赖降到零。

## 3. 系统架构

```
浏览器（电脑 + 手机，同一局域网）
   │  http://<电脑IP>:8787
   ▼
server.js（Node 22 LTS + Hono）
   ├── 静态托管前端页面
   ├── /api/ai/*        AI 代理（SSE 流式，Key 在服务端 data/config.json）
   ├── /api/mistakes/*  错题本 CRUD（data/db.json）
   ├── /api/upload      图片上传（手机拍照直接传）
   └── /api/reports/*   薄弱点画像 / 周报
   ▼
data/ 目录：db.json（错题本+设置）+ uploads/（图片）
```

发行形态：`exam2pdf-portable.zip` = 便携 node.exe（Windows）/ shell 脚本 + node 二进制（Mac）+ 应用代码 + `start.bat`/`start.sh`。解压 → 双击 → 自动开浏览器。

| 架构约束 | 说明 |
|---|---|
| 双击可用 | 解压即用，无安装无编译；启动自动开浏览器；启动前自动清理端口 |
| 数据本地自持 | 全部在 `data/` 目录，备份 = 拷贝目录 |
| AI 降级 | 未配置 Key 时，PDF 合成/打印完全可用 |
| 成本可见 | AI 调用前展示预估消耗，失败不收费 |
| 局域网安全 | 默认仅本机监听；开启局域网需手动操作 |

## 4. 功能需求

### P0-0 小红书采集（内嵌浏览器 + 帖子池）

- **内嵌采集浏览器**：应用内直接打开小红书，无需安装任何浏览器扩展
  - BrowserWindow + `persist:xhs` 会话分区：首次扫码登录，之后免登录
  - preload 预注入「采集到 exam2pdf」按钮（INITIAL_STATE / DOM 双通道提取，prv→dft 提质）
  - 采集结果统一推送本机服务 `127.0.0.1:8787`
- **帖子池**（完整 CRUD）：
- 「采集」屏 = 帖子池，提供完整 CRUD：
  - **查**：帖子列表（封面/标题/张数/日期）+ 点开预览（网格大图 + 灯箱逐页）
  - **增**：脚本推送自动入库；也支持手动导入 zip
  - **改**：重命名标题
  - **删**：删除帖子（连带图片）
- 打印：单帖「合成 PDF → 直接打印」；勾选多帖合并打印
- 与批阅联动：帖子可「加入批阅」直接进入批阅页码列表
- 存储：`data/`（zip 形式），随应用数据一起备份
- 独立油猴脚本（exam2pdf.user.js）保留为可选路径：适合偏好自带浏览器的用户

### P0-1 AI 接入设置

- 提供商预设：DeepSeek（默认）/ 智谱 GLM / 通义千问 / Kimi / 自定义（OpenAI 兼容）
- 配置项：Base URL、模型名、API Key —— 存服务端 `data/config.json`
- 「测试连接」按钮；批阅页显示「已接入 DeepSeek · deepseek-chat」
- 服务端发起 AI 请求，无浏览器 CORS 限制

### P0-2 手机拍照上传

- 手机浏览器访问同一服务 → 批阅页「拍照上传」直接调起相机
- 上传即出现在页码列表，可排序/删除/预览
- 解决「照片先传电脑」的流程断点

### P0-3 批阅结构化

- 批阅提示词要求 AI 同时输出：Markdown 报告（人读）+ JSON 结构化结果（机器存）
- 每题：题号 / 学生作答摘要 / 结果枚举（正确|部分正确|错误|未作答）/ 错因枚举（概念|计算|审题|方法）/ 知识点标签[] / 正确解法摘要
- 批阅完成进入**确认页**：家长逐题修改后入库
- **AI 不直接定稿**，家长确认制是准确率风险的核心控制手段

### P0-4 错题归档

- 确认后一键把「错误/部分正确/未作答」的题写入错题本
- 归档内容：试卷来源 + 题号 + 作答页图 + 错因 + 知识点 + 日期 + AI 解法摘要
- P0 存整页图 + 题号定位；题框裁切留 P2 探索

### P1-1 错题本浏览

- 筛选：时间 / 知识点 / 错因 / 结果；关键词搜索
- 操作：标记「已掌握」/ 重新激活 / 编辑 / 删除
- 概览：累计错题数、知识点分布、本周新增

### P1-2 薄弱点分析（AI）

- 错题本结构化数据（不含图片）发给 AI，生成「薄弱点画像」：
  - Top 薄弱知识点（频次 × 错误模式加权）
  - 错误模式占比：概念不清 / 计算失误 / 审题偏差 / 方法缺失
  - 趋势：与上次分析对比
- 输出学情报告（Markdown 渲染 + 一键导出 PDF）

### P2-1 变式训练（AI）

- 选薄弱知识点 → AI 生成变式练习（默认 5 题）：同知识点、不同考查角度、附完整步骤
- 题目区与答案区分离；显著标注「AI 生成，家长审核后使用」
- 可直接合成 PDF 打印

### P2-2 周报

- 一键/定时生成「本周错题 + 薄弱点变化 + 训练记录」汇总 PDF

## 6. AI 提示词设计要点

1. **批阅与归纳分离**：批阅（带图）与薄弱点归纳（纯文本）分两次调用
2. **JSON 输出容错**：schema 约束 + 正则提取 JSON 块 + 失败自动重试一次
3. **知识点词表约束**：内置小初高知识点树，提示词要求优先从词表选取，保证统计口径
4. **变式题防幻觉**：步骤完整、数值可算、不引用教材原题；家长审核前置
5. **SSE 流式**：批阅报告流式渲染，体感等待减半

## 7. 非功能需求

- 目标环境：Mac / Windows，双平台便携发行；局域网内手机/平板浏览器可用
- 体积：发行 zip < 120MB（主要是便携 node 运行时）；应用代码 < 1MB
- AI 请求可重试；进行中按钮置灰防重复
- 隐私：图片与错题仅存本机；AI 调用是唯一出网行为；提供「清空全部数据」

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| AI 批阅错判 | 家长确认制，可修改后入库 |
| 手写识别质量差 | 拍摄规范引导；识别失败不计入统计 |
| 知识点标签口径混乱 | 词表约束，AI 优先选词表 |
| 局域网暴露 | 默认仅本机监听；开局域网需手动开启；不做公网暴露 |
| 内嵌第三方平台 | 页面改版需适配（双通道提取已增强容错）；README 免责声明醒目；公开仓库措辞保持「个人学习工具」 |
| JSON 并发写 | 单用户低频写 + 原子写回（temp+rename），风险可忽略 |
| Node 版本碎片 | 发行包内置固定版本便携 node.exe/二进制，不依赖对方安装 |

## 10. 技术栈（结论）

| 层 | 选型 | 理由 |
|---|---|---|
| 外壳 | **Electron**（主进程内嵌 Hono） | 内置 Chromium 环境可控、桌面应用形态、自动更新；后端代码与便携 Node 版完全一致 |
| 路由 | **Hono** | 轻量、TS 友好、Node/Bun 双兼容（保留迁移余地） |
| 数据库 | **JSON 文件（data/db.json，原子写回）** | 家庭规模无需 SQLite；零原生依赖；备份即拷贝 |
| AI | 服务端 fetch OpenAI 兼容接口 + SSE | 无 CORS 限制，任意提供商 |
| 前端 | 现有单文件 HTML/JS（由服务托管） | 与 v1.0 复用 |
| PDF/zip | mini-pdf.js + DecompressionStream | 已验证 |
